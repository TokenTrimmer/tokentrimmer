# Learned Compression — Phase 2, Slice P2a (label-gap + corpus hygiene + minimal VCR)

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (one subagent per task). Steps use checkbox (`- [ ]`) syntax, TDD per step.

**Goal:** Close the RUNG 3 label-gap join, clean the P1d capture sink so future gold labels are honest, seed the corpus via default-on catalog routes, cap the RUNG 3 judge tax per-org/per-day, AND ship a minimal **Verifiable Compression Receipt (VCR)** on the existing P1a-d deterministic path — all with ZERO user-visible behavior change on the default path and NO learned model yet. This is the Phase-1→Phase-2 handoff: the proof-of-savings surface ships early (de-risked from the model timeline), and the training data becomes honestly labelable.

**Architecture (owner-resolved 2026-07-06):** the VCR reuses TT's existing Ed25519 audit signing (`TT_AUDIT_SIGNING_KEY`, already in server state as `audit_signing_key`) with a new disjoint `vcr:v1|` canonical-string prefix — mirroring `cloud/.../attestation/crypto.rs`'s `sign_payload_v3`/`verify_payload_v3` shape (canonical ASCII, NOT a `serde_json::Value`). The label-gap closure is mostly a NEW eligibility predicate (`content_compress` added to `maybe_spawn_quality_judge`'s OR-chain at `chat.rs:6057`) + a `request_logs.trace_id` partial index (migration 0034) — the existing `ReferenceSource::Dispatch` already re-runs the served model on the uncompressed `before` (captured pre-routing at `chat.rs:2454`). The judge-cost exclusion from `monthly_cap` + savings is ALREADY TRUE; the only new budgeting piece is a per-org/per-day judge cap. The corpus post-filter replays each captured pair through `PassPipeline::run` (sync, pure, CLI-callable) and drops pipeline-rejected rewrites. Default-on catalog routes = set `content_compress: true` in the `catalog_routes()` const.

**Tech stack:** Rust (`tt-telemetry` VCR, `tt-core` eligibility + emission, `tt-routing` catalog, `tt-cli` export filter + verify command), sqlx migration 0034, `ed25519-dalek` (already a dep), `blake3` (already a dep), `tt_tokenize` (Confidence filter). ## Global constraints (verbatim from the spec + grounding)
- **Zero user-visible behavior change on the default path.** The VCR emits only when a compression actually happens (`content_compress_tokens_removed > 0`); the eligibility + cap + filter are observability/measurement, not controls. A request without `content_compress` opt-in is byte-identical.
- **VCR domain-separation.** A new `vcr:v1|` prefix, disjoint from `att:`/`pdf:v1|`/bare-32B-audit-hash (the test at `pdf_signature.rs:115-139` proves the families disjoint — mirror it). Sign a canonical ASCII string (fixed field order, money rounded to integer micros), NOT a `serde_json::Value` (field order is not stable across serializers — the attestation lesson).
- **VCR fail-open unsigned.** When `TT_AUDIT_SIGNING_KEY` is unset (the default), `audit_signing_key` is `None` → the VCR is omitted (or emitted unsigned) — never crashes, never blocks. Mirrors the PDF-report behavior (`pdf_report.rs:238-246`).
- **Cast direction (critical).** The trace_id join is `quality_verdicts.request_id::text = request_logs.trace_id` (cast THIS side). Casting `request_logs.trace_id::uuid` THROWS on non-UUID values (it's nullable TEXT). Source: `0014_quality_verdicts.up.sql:7-10`.
- **Judge cost excluded from monthly_cap + savings — ALREADY TRUE.** Judge cost flows ONLY through `JudgeSink::record` → `quality_verdicts.judge_cost_usd`; it never reaches `SpendSink::record`/`BudgetEnforcer`. `route_savings.rs:271` itemizes `judge_tax_usd` openly (nets, never silently folded). The ONLY new piece is the per-org/per-day cap.
- **Cloud DB-tests.** Migration + join + cap integration tests are `#[ignore]`d + gate on `TEST_DATABASE_URL` (the cloud CI gotcha). Run locally with a real Postgres; mark them clearly so they don't flake the public CI.
- **No migration for cost attribution.** Savings still book into `content_compress_saved_est_usd` (P1a's field + migration 0033). P2a's migration 0034 is the trace_id partial index ONLY.
